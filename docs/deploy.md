# Публикация демо на бесплатном хостинге (Render)

Публичное демо дополняет локальный запуск (`docker compose up --build --wait`) и не заменяет его.

## Что нужно знать заранее

* **Исходный код остаётся приватным.** Render собирает образ из приватного GitHub-репозитория, публичный Docker-образ и зеркала не создаются.
* **Диск временный.** Бесплатный сервис не хранит файлы между перезапусками: заявки и сессии пропадут, а учётные записи и демо-клиенты пересоздадутся сами (клиенты и источники данных лежат в коде). Для демо этого достаточно.
* **Засыпает через 15 минут простоя**, просыпается 30–60 секунд. Перед проверкой откройте сайт сами; чтобы не засыпал, можно подключить бесплатный пинг `/api/health/live` (например, UptimeRobot) с интервалом 10 минут.
* **Лимит** бесплатного тарифа — 750 часов в месяц на аккаунт (актуальные условия смотрите на странице тарифов Render).
* Образ собирается **без ML** (`WITH_ML=0`): обученной модели нет, режим решения — правила. Переключатель «PD-модель и каскад» в пульте работает на запасном режиме скоркарты.

## Шаги

1. Запушьте проект в **приватный** репозиторий GitHub (`git init`, коммит, `git remote add origin …`, `git push`). Каталоги `data/`, `models/*` и `.env` уже в `.gitignore`.
2. На [render.com](https://render.com) зарегистрируйтесь и подключите GitHub (доступ можно ограничить одним репозиторием).
3. **New → Blueprint** → выберите репозиторий: Render прочитает `render.yaml` (Docker, план free, healthcheck `/api/health/ready`, переменные окружения). Либо **New → Web Service → Docker** и вручную: Runtime `Docker`, Instance Type `Free`, Health Check Path `/api/health/ready`.
4. Дождитесь сборки (3–5 минут). Адрес будет вида `https://credit-cabinet-xxxx.onrender.com`. Порт Render задаёт сам через `PORT` — контейнер его подхватывает.
5. Проверьте: `https://…onrender.com/api/health/ready` → `{"status":"ready"}`; затем войдите кнопками на главной (пароль демо-учёток `demo123`) и пройдите сценарий «Проверка за 5 минут» из README.
6. Добавьте адрес демо в README.

## Обновление и фиксация версии

В `render.yaml` стоит `autoDeploy: false`: стенд обновляется только по кнопке **Manual Deploy**. Так демо не изменится без вашего ведома, а тег и commit hash однозначно определяют версию кода.

## Если что-то не так

| Симптом | Причина и решение |
|---|---|
| «Service Unavailable» минуту после открытия | сервис просыпался; подождите 30–60 секунд и обновите |
| Сборка падает на `pip install` | проверьте, что в репозитории есть `requirements.txt`, `requirements.lock`, `requirements-ml.txt` (Dockerfile копирует все три) |
| Страница без стилей после обновления | кэш браузера; сервер отдаёт статику с `Cache-Control: no-cache`, достаточно Ctrl+F5 |
| Заявки пропали | сервис перезапускался (диск временный) — это ожидаемо; сценарий можно пройти заново |
