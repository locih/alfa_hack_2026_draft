# Модель кредитного процесса

Граница MVP: **действующий клиент банка** (ИП или ООО) → потребность в финансировании → заявка → проверка → решение → предложение → принятие → подписание (имитация) → моделируемая выдача. Регистрация нового клиента, пост-кредитное обслуживание, реальные проводки и интеграции — за границей процесса.

## Участники и действия

| Участник | Действия в процессе |
|---|---|
| Клиент (владелец, директор, бухгалтер) | смотрит предодобрение, подбирает продукт и параметры, подаёт заявку и согласия, отвечает на запрос документов, принимает или отклоняет предложение, подписывает кодом, отзывает заявку |
| Система (конвейер) | проверяет допуск и стоп-правила, собирает данные источников, считает скоринг, платёжеспособность, цену, формирует предложение, ведёт журнал |
| Кредитный аналитик | разбирает заявки серой зоны: одобряет или меняет условия, запрашивает документы, отказывает с причинами из справочника |
| Администратор стенда | ключевая ставка, режим БКИ, режим решения, сброс данных (только демо) |
| Внешние источники (моки) | ЕГРЮЛ/ЕГРИП, ФНС «Прозрачный бизнес», БКИ, внутренние данные банка по оборотам |

## Этапы, данные и результаты

| Этап (шаг степпера) | Статусы | Входные данные | Результат |
|---|---|---|---|
| 1. Заявка | DRAFT | продукт, сумма, срок, обеспечение, цель, согласия (ПДн, БКИ, ФНС) | заявка создана (идемпотентно), событие в журнале |
| 2. Проверка | VERIFICATION, AWAITING_DOCS | ИНН клиента → ЕГРЮЛ, ФНС, БКИ (таймаут, 2 повтора), обороты банка | стоп-правило → отказ; источник недоступен → ручной разбор; иначе → оценка |
| 3. Решение | DECISIONING, MANUAL_REVIEW, OFFER_READY, DECLINED | профиль (14 факторов), продукт, сумма, срок | как просили / встречное (срок → сумма) / другой продукт / ручной разбор / отказ с причинами |
| 4. Подписание | AWAITING_SIGNATURE | принятое предложение | подпись кодом (имитация простой ЭП) |
| 5. Выдача | DISBURSING, DISBURSED | подписанный договор | договор, график платежей, зачисление (мок) |

Возможные исходы: **выдан**, **отказ** (стоп-правило / платёжеспособность / решение аналитика), **отозвана клиентом** или отказ от предложения, **истёк срок** (документы, оферта, подписание).

## Данные о предпринимателе и зачем они нужны

| Данные | Откуда | Зачем |
|---|---|---|
| ИНН, ОГРН, ОКВЭД, руководитель, дата регистрации | ЕГРЮЛ/ЕГРИП (мок) | допуск продукта, возраст бизнеса, отрасль, достоверность |
| Помесячные поступления за 12 месяцев, платежи по кредитам, стаж в банке | внутренние данные банка (мок) | платёжеспособность (DSCR), динамика и стабильность, денежный поток |
| Просрочки, история, обращения, действующие обязательства | БКИ (мок) | кредитная история, стоп-правила |
| Налоговая задолженность, иски, санкционный флаг, реестр МСП | ФНС (мок) | стоп-правила, льготная программа |
| Продукт, сумма, срок, обеспечение, цель | заявка клиента | параметры предложения; клиент вводит только это |

Каждый собираемый параметр используется в скоринге, стоп-правилах, допуске продукта или расчёте платёжеспособности; лишние поля у клиента не запрашиваются (данные о компании подтягиваются автоматически).

## Что видит каждая сторона

* **Клиент** — пять нейтральных шагов, текущий статус, «что дальше / что нужно от вас / когда», предложение с главными цифрами, понятные причины решения. Не видит: внутренние статусы, стоп-правила, источники и их ответы, баллы, PD, комментарии аналитика о рисках.
* **Банк** — полный журнал, ответы источников, разбор по 14 факторам, расчёт платёжеспособности, каскад по продуктам (если включён), рекомендация системы.
