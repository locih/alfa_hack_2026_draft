# Источники данных: что подключить, чтобы модуль работал в проде

Прототип считает всё на синтетических данных, но через те же интерфейсы, что и боевой контур: каждый фактор скоринга, политики и «умного» слоя (радар, лимит) читается из профиля `scoring.build_profile`, который собирают адаптеры источников (`app/mocks.py` — их демо-реализация). Чтобы модуль заработал на реальных данных, нужно заменить адаптеры, не меняя скоркарту, политику и фронт.

| Данные в профиле | Где используется | Демо-источник | Боевой источник |
|---|---|---|---|
| Поступления по счёту за 12 мес., среднее, динамика, изменчивость (`receipts`, `avg`, `dynamics`, `cv`) | скоринг 2.1–2.3, P_max, предодобрение, **радар** (сезонность, тренд, коридор) | `mocks.bank_data` | АБС и процессинг банка; для клиентов других банков — выписка (загрузка файла 1С/Excel, Open API банков), **Alfa API** |
| Расчётный счёт, остаток (`account.balance`) | радар (стартовая точка траектории), оплата платежей | таблица `accounts` | АБС (остатки онлайн) |
| Операционные расходы и их календарь | радар (провалы внутри месяца) | доля (1 − маржа отрасли) по дням выплат | платёжный календарь клиента из АБС: зарплатный проект, регулярные платежи контрагентам, аренда, налоги |
| Маржа и риск отрасли (`industry`, `industry_margin`) | ЧДП и P_max, радар (рынок) | `config/products.yaml` | отраслевые бенчмарки банка по портфелю, Росстат/ФНС (среднеотраслевая рентабельность), **Пульс рынка** (эквайринг по отраслям и городам) |
| Сезонность отрасли и рынка | радар (прогноз поступлений) | тот же месяц год назад по счёту клиента | отраслевой сезонный профиль по портфелю банка, данные эквайринга, макропоказатели ЦБ |
| Возраст бизнеса, статус, недостоверность, дисквалификация | стоп-правила, скоринг 1.1 | `mocks.egrul` | ЕГРЮЛ/ЕГРИП (ФНС), реестр дисквалифицированных лиц |
| Налоговая задолженность, блокировки, иски, реестр МСП, санкции | стоп-правила, скоринг 4.1–4.2, радар (репутация) | `mocks.fns` | ФНС «Прозрачный бизнес», ФССП, КАД арбитраж, реестр МСП, санкционные списки, 115-ФЗ контур банка |
| Кредитная история: просрочки, длина, запросы, обязательства | скоринг 3.1–3.4, радар (репутация, подушка), лимит («дисциплина») | `mocks.bureau` | НБКИ / ОКБ / Скоринг Бюро по согласию клиента; для ИП — история физлица |
| Действующие платежи по кредитам (`existing_payments`) | DSCR, доля платежей, радар (списания 25-го), лимит («рефинансирование») | мок | БКИ (платёжная нагрузка) + собственный портфель банка |
| График платежей по выданным кредитам | радар (списания в даты), «Мои кредиты» | `pricing.schedule` | кредитный модуль АБС, календарные даты и переносы на рабочий день |
| Обеспечение: вид, оценка | ставка, лимит («залог») | селект в заявке | оценка залога (фото + оценщик), реестр залогов ФНП, ЕГРН для недвижимости |
| Подтверждённость данных (`statement_source`) | скоринг 1.4, лимит («выписка») | мок | факт подключения выписки/Open API, дата последней синхронизации |
| Ключевая ставка (`key_rate`) | ценообразование | пульт администратора | ЦБ РФ (ежедневно), казначейство банка |
| Концентрация плательщиков, возвраты, кассовые операции | **не используется в демо** (ограничение) | — | детализация операций по счёту: доля топ-3 плательщиков, доля наличных, возвраты — повышают точность радара и скоринга |
| Рыночные индикаторы отрасли клиента | **не используется в демо** | — | Пульс рынка, индексы деловой активности, цены на сырьё для производства |

## Как подключаются источники

1. Каждый источник — адаптер с единой сигнатурой `fetch(client) -> {"status": "OK" | "UNAVAILABLE", "data": {...}}` (сейчас — функции в `app/mocks.py`). Недоступность источника переводит заявку в ручной разбор, а не в отказ (`service._degrade`).
2. Профиль `build_profile` не меняется при замене адаптера: скоркарта, политика, радар и лимит продолжают работать.
3. Для радара на реальных данных достаточно трёх вещей: выписка за 12 месяцев, остаток счёта, график обязательных платежей; остальные факторы уточняют коридор и подушку.
4. Версии карты и политики фиксируются в каждой заявке (`scorecard_version`, `policy_version`), поэтому переход на реальные данные не ломает историю решений.

## Что это даёт банку

Модуль встраивается как раздел «Кредиты» кабинета и как сервис решений: один профиль клиента → скоринг → политика → лимит → радар. Замена синтетики на источники из таблицы — задача интеграции, а не переписывания логики.
