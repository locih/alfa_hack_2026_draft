## Модели и датасеты

LLM не используются. Основной режим (`rules`) — детерминированные правила без ML.

Опциональный ML-слой (PD-модель, `ml/`, подключается сборкой `WITH_ML=1`) использует открытые библиотеки; **обученные веса в репозиторий не входят** — модель обучается скриптом `ml/train.py` на данных банка. Для проверки конвейера используется синтетика `ml/synth.py` (создаётся нашим кодом, внешних датасетов нет).

| Компонент ML-слоя | Версия | Лицензия | Назначение |
|---|---|---|---|
| LightGBM | 4.6.0 | MIT | градиентный бустинг (обучение и инференс) |
| scikit-learn | 1.7.2 | BSD-3-Clause | калибровка (isotonic / Platt), метрики |
| NumPy, pandas, SciPy | 2.3.3, 2.3.3, 1.16.2 | BSD-3-Clause | данные, KS-тест |

Системная зависимость образа с ML: `libgomp1` (GNU OpenMP, GPL-3.0 с runtime exception).

## Смоделированные интеграции (моки)

| Интеграция | Реализация |
|---|---|
| Бюро кредитных историй | `app/mocks.py::bureau` — синтетический отчёт, управляемый сбой (режим «Сбой» в пульте; для клиента `gromov` — «отвечает» после подключения выписки) |
| ЕГРЮЛ/ЕГРИП | `app/mocks.py::egrul` |
| ФНС «Прозрачный бизнес» | `app/mocks.py::fns` (налоговая задолженность, иски, санкционный флаг, реестр МСП) |
| Внутренние данные банка (обороты) | `app/mocks.py::bank_data` |
| Электронная подпись | код подтверждения в интерфейсе (`service.client_sign`) |
| Зачисление средств | запись о договоре (`service.step_disburse`) |

Все клиенты, ИНН (с нереальным кодом региона `00`), счета и суммы — синтетические.
